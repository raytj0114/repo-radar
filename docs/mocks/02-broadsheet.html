Turbopackキャッシュ、既定を反転

Next.js 16.2.1　移行は一行、影響は全域

米Vercel社のNext.jsは三十一日午後、バージョン16.2.1を公開した。Turbopackの キャッシュ既定値を反転させ全ビルドに適用する変更が柱で、部分プリレンダリング （PPR）の安定版昇格、画像最適化のメモリ使用量四割削減がこれに続く。

既定値の反転そのものは設定一行で追随できる。だが影響はビルドの全域に及ぶ。 従来は明示的に有効化した場合に限られていたキャッシュが、今後はすべてのビルドで 前提となるため、CI側で独自のキャッシュ戦略を組んでいる現場では二重化に注意が 要る。逆に、何も設定してこなかった多数派にとっては、今朝から黙って速くなる類の 変更である。

「速さは機能ではなく、
既定であるべきだ」 ——リリースノート冒頭より（意訳）

16.2系は安定化の系列と目され、PPRの昇格はその総仕上げにあたる。実験フラグの 後ろで二年近く寝かせた機能を、既定有効ではなくまず安定版として出す——この 慎重さに16系の設計思想が見える。次の大きな動きは17系の破壊的変更予告と なろう。本紙は引き続き掃引を続ける。

（観測員）

データ基盤

TypedSQL、複数スキーマへPrisma 6.14　診断ログも増強

Prismaは三十一日未明、6.14.0を公開した。生のSQLに型を与えるTypedSQLが マルチスキーマ構成に対応し、大規模データベースを論理分割して運用する現場でも 型の恩恵が届くようになった。

あわせて接続プール枯渇時の診断ログが詳細化された。プールの問題は再現が難しく、 本番でのみ顔を出す。ログの増強は地味だが、深夜の障害対応の時間を確実に削る類の 改善である。Postgres 18の新JSON関数へのネイティブ対応も入った。

観測手記

今週の紙面は削除の記事ばかり組んでいる。Reactはレガシーと呼ばれて久しい Context APIをついに消し、TypeScriptはenumの数値逆引きを既定で無効にする という。大きなソフトウェアの節目は、何かを足した日ではなく、何かを消せた日に 来るのかもしれない。

機能を足す告知は易しい。消す告知は、それを使っていた誰かの朝を壊す覚悟の 文章になる。リリースノートで最も読み応えがあるのは、いつもBreaking Changes の節だ。そこには設計者が「これはもう間違いだった」と認める瞬間が記録されて いる。私たちが毎朝リリースを読むのは、新機能の目録が欲しいからではなく、 他人の後悔の速報を読みたいからではないか。

依存の系譜　第百三十一回express——十年の静止、その後

Node.jsの標準玄関であり続けたexpressは、v4のまま約十年を過ごした。5.0が形に なったのは二〇二四年の秋。積年の課題だったPromise対応をようやく果たし、 5.1.0（二〇二五年九月）を最後に、また静かになっている。

十箇月の無信号を「停滞」と読むか、「完成」と読むか。HTTPそのものが変わらない 限り、変わらない理由を持つソフトウェアもある。レーダーの外周で動かない輝点は、 死んだのではなく、軌道が安定しているだけかもしれない——ただし、その見極めこそが 観測の仕事である。
